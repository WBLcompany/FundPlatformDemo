# خطة التنفيذ مع Claude Code

**المدة:** من الأحد ٤ أكتوبر إلى الإثنين ٣٠ نوفمبر ٢٠٢٦. ثمانية سباقات أسبوعية (الأحد–الخميس) ويومان للإطلاق.
**القاعدة:** كل سباق ينتهي ببوابة خروج تُختبر، لا بتاريخ فقط. إن لم تُعبر البوابة يُطبَّق خط القطع (القسم ٤) ولا يُؤجل الموعد.

## ١. طريقة العمل مع Claude Code

1. **مهمة واحدة في كل جلسة.** افتح الجلسة بـ `/task T-xx`، فيقرأ Claude Code المهمة من هذا الملف ومتطلباتها من `docs/01-requirements.md`.
2. **خطة قبل كود.** كل مهمة تبدأ بـ plan mode: الملفات التي ستتغير، والاختبارات، والمخاطر. الإنسان يوافق ثم يبدأ التنفيذ.
3. **الاختبار أولاً** لآلات الحالة وجداول القرار والصلاحيات والمال. اسم الاختبار يحمل رقم المتطلب: `it('R-024 every submitted application has an assignee')`.
4. **مراجعة إلزامية** لأي تغيير في RLS أو الترحيلات أو المال: `/rls-review` ثم مراجعة بشرية.
5. **لا دمج بلا بوابات:** lint، typecheck، Vitest، pgTAP، Playwright.
6. **تحديث الحالة:** في نهاية كل مهمة يحدّث Claude Code عمود الحالة في `docs/progress.md` ويكتب أي قرار جديد في `docs/decisions.md`.
7. **الاستضافة ومزود النموذج قراران بشريان** (Q-1، Q-2). Claude Code يجهّز التجربة والمقارنة، ولا يختار.

## ٤. خط القطع

إن تأخرت بوابة، يُبسَّط بهذا الترتيب، الأقل ضرراً أولاً. كل تبسيط يحفظ البنية ويؤجل الواجهة فقط:

1. المورّدون وكتالوج البنود والدعوات، إن أكدت جلسة التحقق أن الملاحي لا يستخدمها الآن.
2. السؤال باللغة الطبيعية: تبقى الطبقة الدلالية، وتُؤجل الخانة.
3. بناء السياسة بالذكاء: وبل تهيئ إطار الملاحي يدوياً.
4. واتساب: البريد وداخل النظام يكفيان للإطلاق.
5. «استخدم مقترحاً جاهزاً» (N-03).

**لا يُقطع مهما تأخر:** العزل، السجل، نسخة الإطار، حجز الميزانية، الحجب قبل النموذج. إضافتها بعد وجود بيانات حقيقية إعادة بناء.
