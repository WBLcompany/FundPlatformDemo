# التشغيل الذاتي (D-23)

الاستضافة الآن محلية على خادم تديره وبل (Q-1). كل شيء على خادم واحد: قاعدة البيانات، والويب، والعامل، وفاحص الفيروسات، ومحوّل PDF، والنسخ الاحتياطي.

## ما يلزم على الخادم

- Docker مع Compose.
- قرص ثانٍ للنسخ الاحتياطية، غير قرص قاعدة البيانات.
- وكيل عكسي بشهادة TLS (nginx أو Caddy) أمام المنفذ 3000؛ لا يُنشر غيره.

## أول تشغيل

```bash
cp deploy/.env.example deploy/.env      # املأ كل قيمة؛ الأسرار: openssl rand -base64 32
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d --build
```

خدمة `migrate` تطبّق الترحيلات قبل أن يبدأ الويب والعامل، وتحفظ سجلاً بما طُبّق وبصمته (`ops.schema_migrations`). لا تحذف شيئاً، وترفض تشغيل ملف تغيّر بعد تطبيقه.

**الإنتاج يرفض الإقلاع إن غاب أي سر.** هذا مقصود، فلا تضع قيماً مؤقتة.

لبيانات العرض فقط، على قاعدة فارغة:

```bash
docker compose -f deploy/docker-compose.yml --env-file deploy/.env run --rm migrate node scripts/migrate.mjs --self-hosted --seed-demo
```

## التحديث

```bash
git pull
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d --build
```

الترحيلات الجديدة وحدها تُطبَّق.

## النسخ الاحتياطي والاسترجاع (R-116)

خدمة `backup` تأخذ نسخة كل يوم إلى `BACKUP_DIR` وتحتفظ بثلاثين يوماً. تحوي كل نسخة:

- القاعدة بصيغة pg_dump المخصصة.
- أدوار القاعدة دون كلمات مرورها.
- مخزن الملفات.
- بصمات الملفات، وتُقرأ النسخة قبل اعتبارها ناجحة.

للاسترجاع إلى قاعدة فارغة على أي خادم:

```bash
PGHOST=… PGUSER=postgres PGPASSWORD=… PGDATABASE=grants AUTHENTICATOR_PASSWORD=… STORAGE_ROOT=… \
  deploy/restore.sh /srv/wbl-backups/20261003-020000
```

السكربت يتحقق من البصمات، ويرفض قاعدة غير فارغة، ويتحقق بعد الاسترجاع من سلسلة التدقيق لكل مانح.

**تجربة الاسترجاع (٢٠٢٦-١٠-٠٣):**

- أُخذت نسخة من قاعدة اجتازت دورة منحة كاملة، واستُرجعت إلى قاعدة فارغة.
- أعداد الصفوف في الجداول الستة والخمسين متطابقة، ومخزن الملفات متطابق، وسلسلة التدقيق سليمة.
- خدمت المنصة القاعدة المسترجعة، ونُزّلت منها الاتفاقية الموقعة.
- أُجريت التجربة بالسكربتات نفسها على عملية Postgres في بيئة التطوير، لا داخل الحاويات.
- تُعاد التجربة على الخادم بعد أول تشغيل، ثم كل ربع سنة.

## ما لم يُختبر بعد

لم تُبنَ الصور ولم يُشغَّل `docker compose up` في بيئة التطوير، لأن سحب الصور الأساسية محجوب فيها. اختُبر كل جزء بمفرده بالسكربتات نفسها، وكان كل ذلك في وضع الإنتاج:

- `migrate.mjs` على قاعدة فارغة: المخطط الناتج مطابق لمخطط التطوير.
- خادم الويب المستقل (standalone) والعامل على القاعدة الناتجة: دخول كل الأدوار، و٢٠ جلسة متزامنة بلا أخطاء.
- النسخ والاسترجاع.

أول `up --build` على الخادم هو اختبار التغليف.
