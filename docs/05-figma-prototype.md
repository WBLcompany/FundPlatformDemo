# النموذج الأولي عبر Figma

**الهدف:** نموذج قابل للنقر بهوية وبل يغطي الرحلات الأساسية، يُراجَع مع الرئيس التنفيذي ثم في جلسة التحقق مع الملاحي **قبل** بناء المنطق، ويصير ملف Figma مرجع التصميم للفريق.

## ١. طريقة العمل: كود ← Figma ← كود

Claude Code لا يرسم في Figma بالفأرة. الطريق الأسرع والأدق: يبني النموذج كشاشات حقيقية بمكونات `packages/ui` ورموز `design/tokens.json`، ثم يدفعها إلى Figma طبقات قابلة للتحرير، فيعدّلها المصمم هناك، ثم يقرأ Claude Code التعديلات ويطبقها على الكود.

```
1. tokens.json  ──► Tailwind preset + متغيرات Figma (Tokens Studio)
2. Claude Code يبني apps/prototype بالمكونات الحقيقية وبيانات وهمية
3. generate_figma_design يدفع كل شاشة إلى ملف Figma كإطارات قابلة للتحرير
4. المصمم ينظّم الصفحات ويضيف روابط النقر (prototype connections) ويحسّن
5. مراجعة مع الرئيس التنفيذي، ثم جلسة التحقق مع الملاحي على النموذج
6. Claude Code يقرأ الإطارات المعدّلة (get_design_context) ويحدّث المكونات
```

الميزة: المكونات المبنية للنموذج هي نفسها مكونات المنتج. لا رسم مرتين.

## ٢. الإعداد

```bash
# Figma MCP البعيد (يتطلب OAuth لحساب Figma)
claude mcp add --transport http figma https://mcp.figma.com/mcp

# داخل Claude Code: /mcp ثم Authenticate لـ figma
```

- أداة الدفع إلى Figma (`generate_figma_design`) تعمل مع الخادم البعيد فقط، لا مع خادم Figma Desktop. إن كان الاثنان مضافين، احذف إعداد Desktop.
- الإنشاء في المسودات (Drafts) متاح لأي مقعد. الكتابة في ملف داخل مشروع الفريق تتطلب مقعد Full وصلاحية تحرير.
- أدوات القراءة المستخدمة في الخطوة ٦: `get_design_context`، `get_screenshot`، `get_variable_defs`.
- ملف Figma: **«وبل · منصة المنح · النموذج الأولي»** في مشروع وبل.

## ٤. الرحلات القابلة للنقر

بيانات وهمية متسقة عبر كل الشاشات (القسم ٦). كل رحلة تبدأ من نقطة دخول الدور.

| # | الرحلة | الدور | الشاشات |
| --- | --- | --- | --- |
| ر١ | من صفحة البرنامج إلى متابعة الطلب | الجمعية | J1 → J2 → J3 → J4 → J5 → J6 → J7 |
| ر٢ | دراسة طلب بنمط «مانح أولاً» | الأخصائي | S1 → S2 → S3 → S4 → S5 |
| ر٣ | دراسة مستقلة: الحجب ثم الكشف | الأخصائي | S2-indep → S2-reveal |
| ر٤ | التعطل والترحيل | مدير المنح | M1 → M2 |
| ر٥ | اللجنة من المحضر | أمين اللجنة | C1 → C2 → C3 |
| ر٦ | الاتفاقية إلى أول تسليم | الأخصائي والجمعية | A1 → P1 → P2 → P3 |
| ر٧ | التنفيذ أو الإرجاع | المالية | F1 → F2 |
| ر٨ | الصورة الكلية والسؤال | المدير التنفيذي | E1 → E2 |
| ر٩ | تهيئة مانح بالذكاء | مدير النظام | G1 → G2 → G3 → G4 |
| ر١٠ | صحة المنصة | مشغّل وبل | O1 |

## ٦. البيانات الوهمية الموحدة

- **المانح:** مؤسسة نورة الملاحي (تجريبي). نسخة الإطار ٢٠٢٦-٠١.
- **البرنامج:** تمكين الأسر المنتجة ١٤٤٨، سقف ٤٠٠,٠٠٠ ريال، ستة معايير:
  وضوح الاحتياج ٢٠٪، ملاءمة الأهداف ١٥٪، منهجية التنفيذ ٢٠٪، واقعية الموازنة ٢٠٪، مؤشرات قابلة للقياس ١٥٪، قدرة الجمعية ١٠٪.
- **الجمعيات:** جمعية البر بالدار البيضاء، جمعية رعاية الأيتام بالخرج، جمعية نماء للتنمية.
- **الطلب الرئيسي:** ط-2026-0417، مطبخ إنتاجي لتمكين ٤٠ أسرة، المطلوب 386,000 ريال، توصية مانح: موافقة بمبلغ معدل 350,000.
- **الفريق:** أخصائيان، مدير منح، أمين لجنة، مالية، مدير تنفيذي.
- كل الأسماء والأرقام وهمية ومعلّمة «بيانات توضيحية» في تذييل النموذج.

## ٨. معايير قبول النموذج

- [ ] الرحلات العشر تعمل بالنقر في Figma دون شاشة مفقودة.
- [ ] كل الألوان والخطوط من المتغيرات، لا قيم حرة.
- [ ] بوابة الجمعية بعرض الجوال للشاشات J4 و J6 و J7.
- [ ] كل مكوّن ذكي معروض بحالاته الخمس في صفحة الحالات.
- [ ] الرئيس التنفيذي راجعه، وملاحظاته مسجلة في تعليقات Figma ومعالجة.
- [ ] استُخدم في جلسة التحقق مع الملاحي، وأسئلة الجلسة الثلاثة عشر لها إجابات.
