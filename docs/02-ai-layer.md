# طبقة الذكاء — AI-first

المنصة لا تحتوي نموذجاً لغوياً ولا prompt. كل ذكاء يأتي من **مانح (S003)** عبر عقد مهام. المنصة تملك ما يحكم القرار: الفحوص الحتمية، والحكم البشري، والسجل.
هذا يحقق «لا يُبنى الشيء مرتين»، ويبقي مانح قابلاً للبيع منفرداً لعملائه.

## ١. أين يظهر الذكاء في التجربة

القاعدة: الذكاء يظهر حيث يعمل المستخدم، بوسم واضح، ومعه زر قبول وزر تعديل وزر «المصدر».

| المستخدم | الشاشة | ما يفعله الذكاء | ما يبقى للإنسان |
| --- | --- | --- | --- |
| مدير النظام | التهيئة | يبني مسودة السياسة من ملفات المانح، ويشتق المعايير والشروط والسلاسل | اعتماد السياسة ثم اعتماد الإعدادات |
| مدير النظام | قائمة الإعداد | يقترح القيم الناقصة من السياسة المعتمدة | قبول كل قيمة |
| الجمعية | رفع الوثائق | يستخرج نوع الوثيقة وتاريخ انتهائها ورقمها | تأكيد القيم |
| الجمعية | نموذج التقديم | يحوّل مقترحاً جاهزاً إلى مسودة النموذج | مراجعة كل حقل قبل الإرسال |
| الأخصائي | مهامي | سطر «ما المطلوب منك» لكل مهمة | — |
| الأخصائي | ملف الدراسة | ملخص، تقييم بالمعايير بدليل، مراجعة الموازنة، اقتراح المسار والجدول، مسودة التوصية | الحكم: الدرجات والمبلغ والجدول والتوصية |
| الأخصائي | المراسلات | مسودة طلب الاستكمال أو سبب الرفض | التحرير والإرسال |
| أمين اللجنة | محضر اللجنة | يستخرج قرار كل طلب من المحضر المرفوع | تأكيد كل قرار |
| الأخصائي | التسليم والتقرير الختامي | يقارن المنجز بالمطلوب في الاتفاقية | قبول أو إعادة أو رفض |
| الأخصائي | طلب التعديل | الفرق والأثر ومخالفة السياسة | التوصية |
| المدير التنفيذي ومدير المنح | لوحة الأوامر | يحوّل السؤال إلى نية استعلام | — |
| الجميع | رأس صفحة العنصر | «الخلاصة الآن» بسطرين (الحالة، ما ينتظر، الخطر) | — |

## ٢. كتالوج المهام

كل مهمة لها: اسم ثابت، ومخطط مدخلات ومخرجات بإصدار (JSON Schema)، وبديل يدوي، وعتبة تقييم.

| المهمة | المدخلات | المخرج | البديل عند التعطيل |
| --- | --- | --- | --- |
| `policy.draft` | ملفات المانح أو إجابات الأسئلة | وثيقة سياسة، كل بند يشير لمصدره | رفع السياسة يدوياً |
| `policy.derive_config` | السياسة المعتمدة | مسودة إطار: معايير وأوزان، جداول أهلية، سلاسل | إدخال الإعدادات يدوياً |
| `document.extract` | ملف وثيقة | {type, number, issue_date, expiry_date, confidence} | إدخال يدوي |
| `proposal.prefill` | مقترح خارجي + مخطط نموذج البرنامج | قيم حقول مع موضع كل قيمة في المصدر | تعبئة يدوية |
| `application.study_file` | الطلب، المرفقات، نسخة الإطار، تاريخ الجمعية | ملخص، درجات بمبرر ودليل، علامات الموازنة، المسار، جدول مقترح، مسودة توصية | ملف دراسة بحقول فارغة |
| `invitation.fit` | البرنامج، قائمة جمعيات مرشحة | ملاءمة كل جمعية بسبب | اختيار يدوي |
| `message.draft` | الغرض، سياق الطلب | نص عربي رسمي قصير | كتابة يدوية |
| `committee.extract` | محضر مرفوع، قائمة الطلبات | قرار ومبلغ لكل طلب مع موضعه في المحضر | إدخال يدوي |
| `deliverable.review` | التسليم، بند الاتفاقية | مطابقة، نواقص، ملاحظات | مراجعة مباشرة |
| `amendment.diff` | النسخة المعتمدة، التعديل، الإطار | الفرق، الأثر، مخالفات السياسة | الفرق الحرفي فقط |
| `final_report.review` | التقرير الختامي، الخطة، الموازنة | المنجز مقابل المخطط، والمصروف مقابل الموازنة | مراجعة مباشرة |
| `performance.propose` | وقائع المشروع | تقييم أداء مقترح بمبرراته | إدخال يدوي |
| `entity.brief` | حالة العنصر وأحداثه الأخيرة | سطران: الوضع الآن وما ينتظر | يُخفى السطر |
| `query.interpret` | السؤال، كتالوج المقاييس، صلاحية السائل | نية استعلام JSON أو «لم أفهم» | البحث العادي |

## ٣. شكل العقد مع مانح

- **غير متزامن:** `POST /tasks` بـ {task_type, tenant_ref, framework_version_ref, inputs, idempotency_key, callback_url} ← {task_id}. النتيجة تعود إلى `POST /api/hooks/manih` موقّعة بـ HMAC وختم زمني، مع `GET /tasks/{id}` احتياطياً.
- **استثناء متزامن:** `entity.brief` و `query.interpret` و `document.extract` قصيرة، تُستدعى بمهلة ١٠ ثوانٍ، وتفشل بهدوء.
- **المخرجات مقيدة بمخطط:** أي نتيجة لا تطابق المخطط تُرفض وتُعاد المحاولة مرة، ثم تُعرض كـ «تعذّر» مع البديل اليدوي.
- **الدليل إلزامي:** كل درجة أو علامة تحمل {file_id, page, span}. الواجهة تفتح الموضع بنقرة.
- **المستندات بيانات لا تعليمات:** مانح يعامل محتوى المرفقات كبيانات غير موثوقة (حماية من حقن التعليمات).

## ٤. ما لا يفعله الذكاء أبداً

- لا يغيّر حالة طلب أو مشروع أو دفعة.
- لا يرسل رسالة لجهة خارجية دون تحرير إنسان.
- لا يحسب رقماً يُعرض كحقيقة: الأرقام من استعلامات النظام.
- لا يقرر الأهلية أو السقف أو الموانع: هذه جداول قرار.
- لا يرى بيانات مانح آخر، ولا يُدرَّب على بيانات العملاء.

## ٥. نمط الدراسة المستقلة

نتيجة مانح تُحفظ كاملة لحظة وصولها، لكن سياسة RLS تحجب حقول الدرجات والتوصية عن الأخصائي حتى يسجّل تقييمه. تسجيله يطلق حدث الكشف، فتظهر المقارنة معياراً بمعيار. الحجب في قاعدة البيانات، لا في الواجهة.

## ٦. الخصوصية

- حجب البيانات الشخصية قبل الإرسال (الهويات، الجوالات، IBAN، أسماء المستفيدين)، وخريطة الإرجاع تبقى في المنصة.
- إعداد `ai_enabled` لكل مانح، وإتاحة كل مهمة بحسب الدور.
- مكان المعالجة يُحسم في Q-2، ويُكتب صراحة في ملف الثقة.

## ٧. السجل

كل نتيجة سجل `ai_output` غير قابل للتعديل: المهمة، النموذج، إصدار الحزمة، hash المدخلات، نسخة الإطار، النتيجة، الأدلة، الكلفة، الزمن. حكم الإنسان سجل منفصل يشير إليها. الفرق بينهما بيانات تقييم دائمة.

## ٨. التقييم

1. **قبل أي ضبط:** عينة الطلبات السابقة من الملاحي بقراراتها تصير مجموعة تقييم (golden set).
2. **المقاييس:**
   - توافق درجة مانح مع الأخصائي لكل معيار (فرق ≤ ١ في ٨٠٪ من الحالات كبداية).
   - نسبة المبررات المسندة بدليل صحيح (≥ ٩٥٪).
   - دقة علامات الموازنة (precision ≥ ٨٠٪).
   - دقة استخراج تاريخ الانتهاء من الوثائق (≥ ٩٥٪).
   - صحة نية الاستعلام على مجموعة أسئلة مرجعية (≥ ٩٠٪).
   - حالات حقن تعليمات في المرفقات: صفر نجاح.
3. **العتبات** تُثبَّت بعد القراءة الأولى للعينة في `evals/thresholds.yaml`، وأي إصدار يتجاوزها لا يُنشر.
4. **التغذية الراجعة** من المستخدمين (N-11) تُضاف للمجموعة أسبوعياً بعد مراجعة.

## ٩. مكونات الواجهة الخاصة بالذكاء

تُبنى مرة واحدة في `packages/ui/ai` وتُستخدم في كل مكان:

| المكوّن | الاستخدام |
| --- | --- |
| `AiBadge` | وسم «اقتراح مانح» بلون ثابت |
| `AiSuggestion` | نص مقترح + قبول / تعديل / تجاهل + تقييم |
| `EvidenceChip` | يفتح الدليل في درج جانبي على الصفحة والمقطع |
| `AiScoreRow` | معيار: درجة مانح، المبرر، الدليل، درجة الإنسان، الفرق |
| `AiPending` | حالة «مانح يجهّز…» مع زمن متوقع، وبديل يدوي فوري |
| `AiFailed` | «تعذّر» مع السبب والبديل اليدوي، دون اعتذار |
| `EntityBrief` | سطرا «الخلاصة الآن» في رأس الصفحة |
| `CommandBar` | ⌘K: بحث، سؤال، إجراءات |
